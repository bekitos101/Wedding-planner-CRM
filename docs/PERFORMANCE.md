# Performance: dashboard load time (NFR-20)

NFR-20 (proposed target): the main dashboard loads within **2 s** on a documented test configuration
and a representative dataset. This document is that documentation. It is generated by
`cd server && npm run perf:dashboard` (script: `server/scripts/perf-dashboard.ts`); re-run it to refresh the numbers.

## Dataset

5 planners, each owning one wedding (5 weddings), 2 active team members per wedding. Per wedding:
200 guests (50% pending, 30% accepted, 20% declined; every 5th with dietary requirements), invitations for 80% of the guests in
mixed states (sent, failed, pending, some revoked), 100 tasks (mixed status, priority, assignee, past and future deadlines),
40 expenses with 120 payments, 20 suppliers, 30 schedule items (some overlapping).

Totals in the database: 15 users, 5 weddings, 10 members, 1000 guests, 800 invitations, 500 tasks, 200 expenses, 600 payments, 100 suppliers, 150 scheduleItems.

## Method

1. Apply migrations to `wedding_organizer_perf`, truncate all tables, seed with `createMany`.
2. Start the app on an ephemeral port and log in as each planner (bcrypt cost of the seeded hashes is 4; login is not measured).
3. For each wedding and each endpoint: 10 warm-up requests (discarded), then 50 measured sequential requests, i.e. 250 samples per endpoint.
   Time = from sending the request until the whole response body is read.
4. Report min / median / p95 / max. Every response is checked to be HTTP 200.

## Conclusion

**Target met.** The dashboard answers in a median of 49.8 ms, p95 65.7 ms and at worst 119.4 ms, against the 2000 ms target (p95 is 30x below it). The slowest request of all three endpoints was 119.4 ms.
The dashboard is computed on every request from stored rows (aggregates and group-bys, no stored totals, FR-59), so these numbers include
all of that work. They measure the backend only (network and Angular rendering are not included) on a single local machine with an
empty cache of other load; a hosted environment will differ, but the margin is large.
